# Arsenale 1.2.2

A small maintenance release. Nothing changes in how Arsenale runs.

## What changed

- **A guard against pushing to the public repository.** A new git pre-push
  hook refuses any branch push to the public release repository
  (`github.com/emadbarandan/Arsenale-Ai-Agent-Company`) and lets only `v*`
  release tags through. Pushes to any other remote are not touched. It
  recognises the https, ssh and `ssh://` forms of the URL, with or without
  `.git`, a trailing slash or a user name in the URL, in any letter case.
- **One set of numbers.** The README, the reference, `package.json` and the
  repository links now agree: 25 agents (an office lead, three heads and 21
  specialists) and 17 office packs. The repository, homepage, issue and
  security-advisory links now point at the real public repository. A new test
  fails when the README or the reference drift from the `agents/` and
  `packs/` folders, or when the version differs between files.
- The contributing guide asks for Node.js 22 or newer, as `package.json` does.

## Why

The public repository is for releases only; day-to-day work belongs in a
private development remote. The hook makes an accidental branch push there
fail on your machine instead of reaching GitHub. The counts and links had
drifted apart across files, so the docs disagreed with what ships.

## Turn on the guard

Run this once in your clone:

```
npm run setup-hooks
```

It sets `core.hooksPath` to `tools/hooks`. The hook is plain Node.js, so it
works the same on Windows, macOS and Linux, as long as `node` is on the PATH
that git sees. Note that `core.hooksPath` replaces `.git/hooks`: any hooks you
kept there stop running. To turn the guard off again, run
`git config --unset core.hooksPath`.
